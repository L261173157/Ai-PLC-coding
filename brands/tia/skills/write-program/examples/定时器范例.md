# 范例 · 多条件 + 定时器(TON 通电延时)· LAD 与 SCL 两版

> 何时用:要写"满足若干条件后,延时 N 秒再动作"这类逻辑(定时器/计数器同理)。
> 配套 [`写程序`](../SKILL.md);LAD FlgNet 规则见 [`SimaticML速查`](../../_reference/simaticml-reference.md)。

**环境**:TIA Portal V21,CPU 1511-1 PN。两版都导入 + 编译 0 错误。

## 目标逻辑

`(Start OR Auto) AND NOT Stop` 成立 → TON 计时 3s → 到时点亮 Lamp。
即:多条件(并联 + 串联常闭)驱动一个**通电延时定时器**,定时到再输出。

---

## 版本一:SCL(path A,最省事)

`tia_block_generate_from_source` 喂:

```scl
FUNCTION_BLOCK "FB_DelayLamp"
{ S7_Optimized_Access := 'TRUE' }
VERSION : 0.1
   VAR_INPUT
      Start : Bool; Auto : Bool; Stop : Bool;
   END_VAR
   VAR_OUTPUT
      Lamp : Bool;
   END_VAR
   VAR
      DelayTimer : TON_TIME;   // IEC 通电延时定时器(单实例,放 Static)
   END_VAR
BEGIN
   #DelayTimer(IN := (#Start OR #Auto) AND NOT #Stop, PT := T#3S);
   #Lamp := #DelayTimer.Q;
END_FUNCTION_BLOCK
```

要点:IEC 定时器声明为 **`TON_TIME`**(FB 放 Static);`#实例(IN:=…, PT:=…)` 调用,读 `#实例.Q`/`.ET`。**逻辑首选这条**,比手写 LAD 简单得多。

---

## 版本二:手写 LAD(FlgNet)—— 完整可复制,已实测

定时器在 LAD 里的真实结构(从某真实工程块导出解码得到):

### 定时器 = 带 `Version` 的 `<Part>`,**不是 Call**

```xml
<Part Name="TON" Version="1.0" UId="30">
  <Instance Scope="LocalVariable" UId="31"><Component Name="DelayTimer" /></Instance>
  <TemplateValue Name="time_type" Type="Type">Time</TemplateValue>
</Part>
```

- **`Version="1.0"` 必须有**(加在 `<Part>` 上;加到 `CallInfo` 会被 schema 拒)。**只有带 Version 的 Part 才允许 `<Instance>` 子元素**。
- 实例 `DelayTimer` 在接口 **Static** 段声明为 **`TON_TIME`**。
- 接点只有 **`IN` / `PT`(输入)、`Q` / `ET`(输出)——没有 `en`/`eno`**(定时器盒不带使能脚)。
- `TON`→通电延时、`TOF`→断电延时、`TP`→脉冲,结构同(改 `Name`)。

### 接线逐条(13 根 wire)

| Wire | 连接 | 作用 |
|------|------|------|
| 40–42 | 访问 → 触点 `operand` | 绑定 Start/Auto/Stop 标签 |
| 43 | **Powerrail** → 26.in + 27.in | 一根母线进 Start、Auto 两并联触点 |
| 44/45 | 26.out/27.out → O 的 in1/in2 | 两触点并联进或门 |
| 46 | O.out → 29.in | 或门出 → Stop 常闭 |
| 47 | 29.out → **30.IN** | 条件链 → 定时器 IN(**无 en**) |
| 48 | 常量 T#3S → **30.PT** | 预置时间 |
| 49 | **30.Q** → 32.in | 定时到 → 线圈 in(Q 可直驱线圈) |
| 52 | **30.ET** → `<OpenCon>` | 不用的 ET 输出接开放桩 |
| 50 | Lamp → 32.operand | 线圈地址 |

### 关键坑(都已实测)

| 坑 | 正解 |
|----|------|
| 定时器当 Call 写 → 被逼接 `en`、再各种母线报错 | 定时器是 **`<Part Name="TON" Version="1.0">`**,没有 en |
| Part 加 `<Instance>` 报"invalid child" | 是因为**漏了 `Version`**;带 Version 的 Part 才允许 Instance |
| 声明的输出(Q/ET)必须接线,又不想用 ET | ET 接 `<OpenCon UId="x" />`(开放桩),不用建临时变量 |
| 一个网络两根 `<Powerrail/>` wire | 只能一根,所有母线点并进同一根 |
| 时间常量 `T#3S` 报类型错 | `Scope="TypedConstant"` 且**不带** `<ConstantType>` |

## 结论

- **首选 SCL**:定时器/计数器/状态机,SCL 最省事。
- **手写 LAD 也已打通**:多分支 + IEC 定时器可从零手写(本范例);拿不准的指令(其它 FB 块/复杂指令)仍可用「导出模板 → 改 → 重导入」更稳(见 [`SimaticML速查`](../../_reference/simaticml-reference.md))。
