# PLC 工程方法论 · 连接

连接是所有操作的地基。连不稳、模式选错,后面全白干。

## 先选安全模式
见 overview 的安全模式表。原则:
- **摸底/读程序** → 只读(最安全,不会误写)。
- **写程序/组态** → 读写。
- **真机下载/运行/停车** → 不受限 + `confirm=true`。

## 连接的两种姿态(几乎所有工程软件通用)
| 姿态 | 含义 | 何时用 |
|---|---|---|
| **挂接(attach)** | 复用一个**已经打开**的工程软件实例 | **首选**;尤其自动化实例卡死/握手超时时,让人在 GUI 里开好工程再挂 |
| **新建实例(spawn/headless)** | 起一个新进程(可带界面或无界面) | 全自动批处理、无人值守 |

⚠️ 挂接 = 直接操作用户实时工程,**写操作真的会改且不会自动保存**。实验完要么别保存、要么手动撤销。
⚠️ 反复强杀自动化实例会污染许可/IPC 栈,之后新实例握手卡死——遇到就改挂接,或重启清状态。

## 工程生命周期
通用动作(各品牌工具名不同,见品牌 skill):打开 / 新建 / 保存 / 另存 / 关闭 / 归档。
- **一个会话通常同时只能开一个工程**——开/建新的前先关当前的。
- **项目锁由后台进程持有**,不是 GUI 窗口。重连提示"已被打开"时,真凶常是上个会话残留的后台进程——杀掉它立即释放(别傻等)。

## 操作系统前置(一次性,品牌 skill 给具体步骤)
- 工程软件装好(含自动化/Openness 组件)。
- 当前用户在软件要求的**本地用户组**里(否则连接抛 COM/权限异常,加完要注销重登刷新令牌)。
- 构建原生 worker(若能力层用了独立 worker 进程)需要对应的 SDK/Dev Pack。

## 校验
- 连上后 `status` 应返回正常,且**生效模式 = 你启动时选的**。
- 读工程元信息(名/路径)能成功。

## 常见报错 → 通用修法
| 报错 | 修法 |
|---|---|
| 连接抛 COM/权限异常 | 用户没进要求的本地组,或没注销重登 |
| "另一个工程已打开" | 先关当前工程 |
| "已被用户打开…等几分钟" | 杀掉上个会话残留的后台进程 |
| 自动化实例卡死不返回 | 残留进程污染;清进程/重启,改挂接 |
| 重启后端后首次连接握手超时 | 新实例首次握手慢;重试一次 |
