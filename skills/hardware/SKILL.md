# PLC 工程方法论 · 硬件配置

通用铁律:**先硬件,后程序**。先把物理拓扑配好、IO 点映射成符号,再写逻辑——否则地址一变,程序全返工。

## 流程
1. **建设备/CPU** —— 从硬件目录按订货号/型号查到精确标识,建设备。
2. **插模块** —— 按机架/槽位顺序插信号模块、通信模块。
3. **配网络** —— 以太网/现场总线:站名、IP/掩码、子网、IO 系统(分布式 IO)。
4. **配 CPU 选项** —— 系统/时钟位、启动行为、保护等级等(品牌相关)。
5. **IO 点表 → 符号/变量** —— 把物理点(%I/%Q、I/O 地址)命名成有意义的符号,程序里只用符号。

## IO 点表(强烈建议先做)
一张表:物理点 / 模块 / 通道 / 地址 / 符号名 / 注释 / 所属工位。程序、HMI、接线都以它为**单一事实源**。先点表后编程,符号命名一致、地址不冲突。

## 网络
- 以太网:控制器 IP、子网、是否走分布式 IO(如 PROFINET / EtherNet/IP / CC-Link IE)。
- 现场总线:站名、波特率、节点号(品牌相关,见品牌 skill)。
- 规划好命名,别用默认 `PN/IE_1` 之类无意义名。

## 命名(配合公司标准)
- 设备/站:`OP<NN>_<功能>`(工位实例)。
- 子网/IO 系统:有意义的业务名。
- 详细命名规范见 `standards/<company>/` 或品牌 skill 的 `_reference/naming`。

## 编译
硬件配完先编译硬件部分,确认 0 错误(模块冲突、地址重叠、网络未连都会在编译期报出),再进编程。
