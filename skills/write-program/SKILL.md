# PLC 工程方法论 · 编程

## 顺序:类型 → 变量 → 逻辑 → 编译
1. **先建数据类型(UDT/结构)** —— 把设备/工位的接口(状态位、指令位、参数、反馈)定义成自定义类型,这是复用的基础。
2. **再建变量/符号** —— IO 点表映射来的符号 + 实例化 UDT 的 DB/变量。
3. **再写逻辑块** —— 组织块(主循环/中断)/ 功能块(带状态的设备逻辑)/ 功能(纯函数)/ 数据块。
4. **编译到 0 错误** —— 再处理警告。

## 语言选择(按 IEC 61131-3,品牌名不同)
| 类型 | 适合 |
|---|---|
| 文本(ST/SCL) | 复杂运算、状态机、数组/字符串处理——**逻辑首选** |
| 梯形(LD/LAD) | 布尔联锁、自保持、维护工看懂的简单逻辑 |
| 功能块(FBD) | 模拟量、闭环控制 |
| 顺序功能图(SFC/GRAPH) | 工步流程、顺序控制 |

别用梯形写复杂状态机,也别用文本写一目了然的启保停——选对语言省一半事。

## 编程要点
- **IO 用符号引用**,不要裸地址(`%I0.5`)——地址会变,符号不会。
- **设备逻辑封装成功能块**(带 UDT 接口),主程序只做调用 + 互联。别在主循环里堆一坨裸逻辑。
- **先 Fake/离线验证,再上真机**——能力层有 Fake 后端就先跑通逻辑,别拿真机调试。
- **代码必须有清晰中文注释**——块 / 类型顶部写用途,每个管脚 / 成员一句注释,关键逻辑注释意图。具体写法见品牌 write-program 的「代码注释」小节。

## 编译到 0 错误
- 类型未定义 / 引用不存在 / 接口不匹配 = 编译报错,必须清零。
- 警告(未使用变量、隐式转换)次优先,但别留一堆。
- 改块接口(加/删管脚)后,所有调用点都要重编译——接口变动是连锁的。
