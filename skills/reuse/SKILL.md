# PLC 工程方法论 · 复用

每个工位都要气缸、伺服、阀、IO 监控——别每个站重写一遍。沉淀成库,实例化复用。

## 两层模型(通用,公司标准通常以此为准)
- **可复用设备库块** `G_*` —— 母版/模板:某类设备的标准逻辑 + UDT 接口,跨工程共享。
- **站点实例** `OP<NN>_*` —— 具体工位:调用库块、填本工位的实例参数(地址、编号、报警阈值)。

## 流程
1. 建库块(或从已有库引入):设备 UDT + 功能块,输入/输出/状态接口齐全。
2. 实例化:在工位程序里调用库块,绑定到本工位的符号/变量。
3. 编排:工位的 `OP<NN>_Call` / 主程序把各设备实例串起来。
4. 数组化:同类多设备(10 个气缸)用数组 UDT + 循环调用,别复制 10 份。

## 库的形态(品牌相关)
- 全局库文件(如 TIA 的 `.al21`)、母版(Master Copy)、Add-On Instruction、用户功能块库。
- 见品牌 skill 的具体打开/列举/实例化工具。

## 命名(配合公司标准)
- `G_FB<NNN>_<DeviceType>` 库块母版(如 `G_FB500_Cylinder`)。
- `OP<NN>_<功能>` 站点实例(如 `OP10_Valve`)。
- 详细见 `standards/<company>/` 与品牌 `_reference/naming`。

## 何时该建库块
- 同类逻辑出现 ≥2 次 → 抽库块。
- 设备逻辑稳定 → 沉淀进库,新工程直接实例化。
- 别过早抽象:只用一次的逻辑别急着建库。
